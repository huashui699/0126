## 高危发现与修复

### 手工操作可绕过绿色硬门禁

原有 `record_reliability_assessment` 会校验官方来源门禁，但 `apply_review_action('set_trust', ..., 'confirmed')` 直接更新 `news.trust_status`。持有管理员密钥的操作员可以把未批准、非官方或模拟数据改为绿色，违反“绿色 precision = 100%”硬门禁。

仓库修复：

- 新增数据库级 `news` 触发器，所有 AI、API、RPC 和直接 SQL 写入统一校验：官方、身份已验证、采集已批准、直接官方声明、非模拟。
- 来源的官方/身份/批准门禁被撤销时，关联绿色新闻自动降为蓝色、进入复核队列，并追加状态历史。
- pgTAP 增加函数和触发器存在性检查。

### 管理输入与错误信息边界不足

原 API 主要依赖数据库拒绝无效枚举/UUID，并把数据库错误文本返回浏览器。

仓库修复：

- API 层限制 action、trust status、UUID、原因 3–500 字符、操作者 3–200 字符。
- 不再把底层数据库错误详情返回客户端。
- 管理员和 Cron 密钥配置短于 32 字符时一律拒绝鉴权；示例环境变量同步说明。

### 公开展示正文边界

原采集层最多保存 2,000 字符正文摘录并直接写入公开 `news.content`。仓库修复后，原始受控表仍可保留处理所需摘录，公开展示库只写入来源摘要，或最多 600 字符的降级摘录，继续保留原文链接与署名。

## 已通过的仓库证据

- 内部 AI、引用、评估、复核和历史表启用 RLS；匿名和普通登录用户无内部表权限。
- 管理函数只授予 `service_role`；公开历史通过净化视图和列级权限读取。
- 管理与采集 API 均在创建 service client 前完成常量时间密钥校验。
- `.env*` 默认忽略，`.env.example` 只含占位符；服务密钥没有 `NEXT_PUBLIC_` 前缀。
- 隐藏、恢复、合并和撤销均追加审计，不通过物理删除抹去历史。
- lint、TypeScript 与 Next.js 生产构建通过。
