# Day 41 人工评测运行手册

> 启动日期：2026-08-09  
> 当前状态：评测契约与自动计分已完成；真实人工样本 0/300，Day 41 尚未通过

## 实际标注入口

启动本地应用后打开：<http://localhost:3000/admin/evaluation>

1. 填写当前人员代号，点击“新增样本”或先下载 JSON 模板批量准备来源信息。
2. 在“A 独立标注”完成标签、球队、事件簇、摘要忠实度与理由。
3. 第二名人员换用不同代号，在“B 复核裁决”冻结人工最终答案。
4. 人工答案冻结后，在“系统预测”录入系统标签、球队和事件簇。
5. 页面自动保存到当前浏览器并更新 Day 41 门禁；定期点击“导出工作区”备份。

首版标注台不写入 Supabase，不适合多台设备同时编辑同一工作区。跨设备交接使用“导出工作区/导入 JSON”，并确保同一时间只有一份主工作区。

## 目标与硬门禁

Day 41 使用至少 300 条真实、可授权访问的内容，由两名不同人员完成标注与裁决。合成 Feed、自动生成样本和模型自评只能用于契约测试，不能计入 300 条人工集。

必须同时满足：

- 标签一致率 ≥ 85%。
- 预测为绿色的样本 precision = 100%；没有绿色预测不能视为通过。
- 预测为同一事件簇的样本对 precision ≥ 90%；没有正例对不能视为通过。
- 每条样本具备至少两名不同贡献者的标注/裁决记录。
- 实体 precision/recall 与摘要忠实率必须输出到评测报告；仍沿用 Day 33 的实体 precision ≥ 95%、recall ≥ 90% 和 Day 35 的摘要忠实率 ≥ 95% 作为发布门禁。

## 数据契约

每条样本映射为 `ManualEvaluationSample`：

| 字段 | 说明 |
|---|---|
| `sampleId` | 去标识化且唯一的样本编号 |
| `provenance` | 固定为 `human_annotated_real` |
| `annotatorIds` / `adjudicatedBy` | 标注人与裁决人代号；至少两名不同人员 |
| `referenceTrustStatus` / `predictedTrustStatus` | 人工裁决标签与系统标签 |
| `referenceTeamIds` / `predictedTeamIds` | 人工球队实体与系统球队实体 |
| `referenceClusterId` / `predictedClusterId` | 人工事件簇与系统事件簇；无簇时为 `null` |
| `summaryFidelityPassed` | 人工确认摘要是否保留数字、人名、主体、不确定性和关键事实 |

原文只保留必要的来源 URL、标题、短引用和内容哈希；不把未授权全文提交到仓库。标注数据应存放在受控数据位置，仓库只保存去标识化评测输入和汇总报告。

## 执行顺序

1. 从获准来源按球队、信息类型、语言、可信度和聚类难度分层抽样 300 条；绿色候选与同事件正例对必须有足够覆盖。
2. 标注员 A 独立标注；标注员 B 复核分歧并完成裁决，不查看系统预测以减少锚定偏差。
3. 导出符合 `ManualEvaluationSample[]` 的去标识化数据，调用 `runManualEvaluation` 生成报告。
4. 将错误按绿色误标、标签分歧、漏/错球队、错误合并、摘要事实损失分类进入错误台账。
5. 任一绿色误标立即阻断发布；修复后必须使用冻结测试集重新评测，不能删除失败样本。
