## 1. 状态定义

| 状态 | 定义 |
|---|---|
| 已上线 | 代码、数据、权限和生产部署均已验证 |
| 已完成 | 该阶段要求的交付物已完成并通过检查 |
| 已定义 | 需求/设计已写清，但尚未开发或尚未通过最终验收 |
| 进行中 | 已开始执行，仍缺少部分验收证据 |
| 未开始 | 尚未产生实现或阶段交付物 |
| 受阻 | 缺少授权、外部依赖或关键决策，无法继续 |

## 4. 当前 Preview 与目标 MVP 的边界

当前 Preview 已具备：

- 根路径响应式月历与每日绿/蓝/红数量。
- 左上角球队选择弹窗和浏览器本地保留。
- 日期当天摘要、新闻内容、来源、时间与可信度理由。
- Supabase `news` 表匿名只读和数据库失败预览兜底。
- 登录、注册及账号入口按首版决策暂时隐藏。

下列内容不得标记为“已完成”：登录同步、来源自动采集、AI 翻译摘要、绿/蓝/红自动判定、完整状态历史、运营后台、通知和完整监控。

## 8. 后续变更控制

### 8.1 2026-08-08 首版体验调整

- 首版默认入口由资讯首页/日程切换为月历。
- 未选球队时展示全部内容；球队选择改为左上角弹窗，不再阻断首次访问。
- 日期点击后在月历下方展示当天摘要，再进入新闻详情查看内容和来源。
- 登录、注册、账号同步延后到第一版核心体验完成后；既有数据库结构保留但不暴露 UI。


每完成一个 Day，必须执行以下检查：

1. 将当日交付物映射到本矩阵中的需求 ID。
2. 只有同时具备实现、检查结果和可复核证据时，功能才能标为“已完成/已上线”。
3. 新需求必须标明 P0/P1/P2、依赖、验收标准和对 45 日排期的影响。
4. 发现文档冲突时，记录原状态、决策和修改结果。
5. 任何来源在 Day 3 审核通过前不得进入生产自动采集。
6. 每周 M0–M5 里程碑评审时复核未实现 P0、范围新增和延期风险。
7. 新的核心业务能力必须通过平台无关服务/API 表达；若只能在 Web 页面内使用，不能通过架构评审。
